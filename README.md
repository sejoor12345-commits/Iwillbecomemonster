# 🏋️ I will become monster — 헬스 기록 분석기

아이폰 메모에 적던 운동 기록을 **Colab에 붙여넣으면**, 표로 바꾸고 성장을 계산해서 **다음 운동의 무게·세트**를 제안해 주는 노트북입니다.
「코딩실력 늘리기」의 세 번째 빈 화면 테스트 (첫 Python/Colab 프로젝트)예요.

- 파일: `gym_log.ipynb` (노트북 하나로 끝)
- 열기: Colab → `파일 → 노트북 열기 → GitHub` → "비공개 저장소 포함" 체크 → 이 저장소와 브랜치 선택 → `gym_log.ipynb`

## 1. 문제 카드

| 칸 | 내용 |
|---|---|
| 불편한 장면 | 헬스할 때 아이폰 메모에 기록한다. 적기만 하고, 성장했는지·다음에 몇 kg을 들지 판단할 수 없다 |
| 입력 자료 | 아이폰 메모: 날짜, 종목, 무게, 횟수, 세트 |
| 원하는 결과 | 총 세트·총 볼륨, 종목·부위별 성장, 근거에 따른 주간 세트 판정, 다음 무게·세트 제안 |
| 사용 장면 | 나, 운동 끝나고 또는 주말에 한 번 (사지방 PC의 Colab) |
| 제약 | 사지방: Colab + GitHub만 가능. 의학적 처방이 아니라 일반적인 트레이닝 가이드 수준 |
| 성공 기준 | 실제 메모를 붙여넣어 경고 없이 읽히고, 다음 운동 때 제안된 무게로 3번 이상 해 보기 |

**불편을 둘로 나눴어요.** ① 적는 게 불편하다(입력) ② 적어도 쓸모가 없다(분석).
v0.1은 **②부터** 풀어요: 오늘 Colab으로 바로 되고, 지금까지 쌓인 메모를 버리지 않고 바로 데이터로 쓸 수 있고, 여기서 정한 표 모양이 나중에 ① 모바일 앱의 설계도가 되기 때문이에요.

## 3. v0.1에서 넣은 것 / 뺀 것

| ✅ 넣음 | ❌ 뺌 (이유) |
|---|---|
| 메모 형식 그대로 읽기 (`60x10`, `60x10x3`) | **모바일 입력 앱** — 입력 방법보다 표 설계가 먼저. 표가 정해지면 앱은 같은 표에 줄을 추가하는 화면일 뿐 |
| 날짜별 종목 수·총 세트·총 볼륨 | **휴식 시간** — 세트마다 손으로 적기 번거로움. v0.4 타이머가 자동으로 기록하게 |
| 종목·부위별 성장 (e1RM, 볼륨: 첫날 vs 최근) | **RPE** — 없어도 첫 판단은 가능. v0.2에서 `60x10@8`처럼 선택 입력 |
| 부위별 주간 세트 vs 근거 (10~20세트) | **그래프** — Colab 그래프는 한글 폰트 설치가 필요해서 에러 원인이 늘어남. 첫 버전은 표만 |
| 다음 무게(2회 연속 성공 → 증량) · 다음 세트 | **데이터 저장** — 원본은 아이폰 메모에 계속 있음. Colab은 저장소가 아니라 계산기 |
| 이해 못 한 줄·모르는 종목 경고 | **간접 세트 계산** (벤치프레스의 삼두 자극 등) — 규칙이 복잡해짐 |

## 4. 데이터 흐름

```
① MEMO (글자 덩어리, str)
     │  parse_memo(): 한 줄씩 → 빈 줄 / 날짜 줄 / 운동 줄 판단
     │  "60x10x3" → parse_set() → (60.0, 10, 3) → 세트 3개
     ▼
② rows (list of dict)   세트 하나 = dict 하나
     [{"날짜": 9/14, "종목": "벤치프레스", "세트": 1, "무게": 60.0, "횟수": 12}, ...]
     │  pd.DataFrame(rows) + 열 추가: 부위(사전 찾기), 볼륨(무게×횟수), e1RM(공식)
     ▼
③ df (표: 한 줄 = 한 세트)
     ├─ groupby(날짜)                    → ⑤ 날짜별 요약
     ├─ groupby(종목, 날짜) → 첫날 vs 최근 → ⑥ 성장
     ├─ 최근 7일 → groupby(부위) → 세트 수 → ⑦ 주간 판정
     └─ groupby(종목) → 날짜별 (무게, [횟수들]) → next_weight / next_sets → ⑧ 다음 목표
```

**핵심 설계: "한 줄 = 한 세트".** 표를 가장 잘게 쪼개 두면 총 세트는 "줄 세기", 총 볼륨은 "더하기", 주간 세트는 "날짜로 거르고 줄 세기"가 돼요. 나머지는 전부 `groupby`(묶어서 계산)예요.

## 5. 근거

- 주간 세트: Schoenfeld BJ, Ogborn D, Krieger JW. Dose-response relationship between weekly resistance training volume and increases in muscle mass. *J Sports Sci.* 2017;35(11):1073–1082.
- 증량 규칙: American College of Sports Medicine. Progression models in resistance training for healthy adults. *Med Sci Sports Exerc.* 2009;41(3):687–708. (목표 횟수를 1~2회 넘기는 날이 2회 연속이면 2~10% 증량)
- 반복 범위: Schoenfeld BJ, et al. Strength and hypertrophy adaptations between low- vs. high-load resistance training. *J Strength Cond Res.* 2017;31(12):3508–3523.
- e1RM: Epley 공식 `무게 × (1 + 횟수/30)` (Epley B, 1985). 횟수가 많을수록 부정확.
- (v0.2 예정) RPE/RIR: Zourdos MC, et al. *J Strength Cond Res.* 2016;30(1):267–275.
- (v0.4 예정) 휴식 시간: Schoenfeld BJ, et al. *J Strength Cond Res.* 2016;30(7):1805–1812.

## 6. 한계

- 연구 기준은 **평균적인 결과**라서 개인차가 있어요. 통증·부상이 있으면 이 제안보다 몸 상태가 우선이에요.
- 증량은 2.5kg 고정이라 가벼운 덤벨 운동에는 너무 클 수 있어요 (`INCREMENT_KG`로 조절).
- 부위가 주 10세트 미만이면 그 부위 **모든 종목에 +1세트**를 제안하는 단순한 규칙이에요.
- 메모 형식이 다르면 "이해 못 한 줄"로 빠져요. 실제 메모에 맞춰 `parse_set`을 고치면 돼요.
