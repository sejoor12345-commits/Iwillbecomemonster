# 🏋️ I will become monster — 헬스 기록 분석기

아이폰 메모에 적던 운동 기록을 **Colab에 붙여넣으면**, 표로 바꾸고 성장을 계산해서 **다음 운동의 무게·세트**를 제안해 주는 노트북입니다.
「코딩실력 늘리기」의 세 번째 빈 화면 테스트 (첫 Python/Colab 프로젝트)예요.

- 파일: `gym_log.ipynb` (헬스 기록), `weight_log.ipynb` (체중 · 칼로리, v0.3)
- 열기: Colab → `파일 → 노트북 열기 → GitHub` → "비공개 저장소 포함" 체크 → 이 저장소와 브랜치 선택 → `gym_log.ipynb`

## 1. 문제 카드

| 칸 | 내용 |
|---|---|
| 불편한 장면 | 헬스할 때 아이폰 메모에 기록한다. 적기만 하고, 성장했는지·다음에 몇 kg을 들지 판단할 수 없다 |
| 입력 자료 | 아이폰 메모: 4분할(가슴·등·어깨·하체)별로 종목, 무게, 횟수, 세트 (`◦ Bench press: 85*8*4`, `◦ Pull up: 13,12,11`, `✓` = 그날 안 한 운동). 날짜는 안 씀 (교대근무라 운동하는 날이 불규칙) |
| 원하는 결과 | 회차별 총 세트·총 볼륨, 같은 분할끼리 비교한 종목별 성장, 한 사이클의 부위별 세트, 종목별 반복 범위에 따른 다음 무게 제안 |
| 사용 장면 | 나, 운동 끝나고 또는 주말에 한 번 (사지방 PC의 Colab) |
| 제약 | 사지방: Colab + GitHub만 가능. 의학적 처방이 아니라 일반적인 트레이닝 가이드 수준 |
| 성공 기준 | 실제 메모를 붙여넣어 경고 없이 읽히고, 다음 운동 때 제안된 무게로 3번 이상 해 보기 |

**불편을 둘로 나눴어요.** ① 적는 게 불편하다(입력) ② 적어도 쓸모가 없다(분석).
v0.1은 **②부터** 풀어요: 오늘 Colab으로 바로 되고, 지금까지 쌓인 메모를 버리지 않고 바로 데이터로 쓸 수 있고, 여기서 정한 표 모양이 나중에 ① 모바일 앱의 설계도가 되기 때문이에요.

## 4. 데이터 흐름

```
① MEMO (글자 덩어리, str)
     │  parse_memo(): 한 줄씩 → 빈 줄 / ✓ 줄 / 분할 줄(회차 +1) / 운동 줄 판단
     │  "60x10x3" → parse_set() → (60.0, 10, 3) → 세트 3개
     ▼
② rows (list of dict)   세트 하나 = dict 하나
     [{"회차": 1, "분할": "가슴", "종목": "Free IBP", "세트": 1, "무게": 80.0, "횟수": 9}, ...]
     │  pd.DataFrame(rows) + 열 추가: 부위(사전 찾기), 볼륨(무게×횟수), e1RM(공식)
     ▼
③ df (표: 한 줄 = 한 세트)
     ├─ groupby(회차, 분할)                         → ⑤ 회차별 요약
     ├─ groupby(분할, 종목, 회차) → 첫 회차 vs 최근 → ⑥ 성장
     ├─ 분할마다 최근 회차만 → groupby(부위) → 세트 수 → ⑦ 사이클 세트
     └─ groupby(분할, 종목) → 최근 회차 본 세트 + ②설정 → next_weight → ⑧ 다음 무게
```

**핵심 설계: "한 줄 = 한 세트".** 표를 가장 잘게 쪼개 두면 총 세트는 "줄 세기", 총 볼륨은 "더하기", 사이클 세트는 "최근 회차로 거르고 줄 세기"가 돼요. 나머지는 전부 `groupby`(묶어서 계산)예요.

## 5. 근거

- 주간 세트(참고용, v0.1에서는 판정 안 함): Schoenfeld BJ, Ogborn D, Krieger JW. Dose-response relationship between weekly resistance training volume and increases in muscle mass. *J Sports Sci.* 2017;35(11):1073–1082.
- 증량 규칙(참고: 내 규칙은 '모든 세트가 범위 최대 달성 → 1번에 증량'): American College of Sports Medicine. Progression models in resistance training for healthy adults. *Med Sci Sports Exerc.* 2009;41(3):687–708. (목표 횟수를 1~2회 넘기는 날이 2회 연속이면 2~10% 증량)
- 반복 범위: Schoenfeld BJ, et al. Strength and hypertrophy adaptations between low- vs. high-load resistance training. *J Strength Cond Res.* 2017;31(12):3508–3523.
- e1RM: Epley 공식 `무게 × (1 + 횟수/30)` (Epley B, 1985). 횟수가 많을수록 부정확.
- RPE (v0.2): Zourdos MC, et al. *J Strength Cond Res.* 2016;30(1):267–275. / Helms ER, et al. Application of the repetitions in reserve-based rating of perceived exertion scale for resistance training. *Strength Cond J.* 2016;38(4):42–49. (내 규칙: 범위 최대 달성 + RPE 9 이하 또는 안 씀 → 증량, RPE 10 → 같은 무게로 굳히기)
- 체중 1kg ≈ 7700kcal: Wishnofsky M. *Am J Clin Nutr.* 1958;6(5):542–546. (대략값. 장기적으로는 과대평가된다는 비판: Hall KD. *Int J Obes.* 2008;32(3):573–576.)
- 감량 속도 주당 체중의 0.5~1%: Helms ER, Aragon AA, Fitschen PJ. Evidence-based recommendations for natural bodybuilding contest preparation. *J Int Soc Sports Nutr.* 2014;11:20.
- (v0.4 예정) 휴식 시간: Schoenfeld BJ, et al. *J Strength Cond Res.* 2016;30(7):1805–1812.

## 6. 한계

- 연구 기준은 **평균적인 결과**라서 개인차가 있어요. 통증·부상이 있으면 이 제안보다 몸 상태가 우선이에요.
- 설정에 없는 종목은 기본값(8~12회, 5kg)으로 계산해요. `EXERCISES`에 추가하세요.
- 세트 뒤에 숫자만 따로 쓰면 횟수로 읽어요 (예: `60*12,12 휴식 90` → 90회 세트로 읽힘).
- 맨몸 운동(②에서 증량 0)의 `12*3`은 "12회 × 3세트"로 읽어요. 중량 풀업처럼 무게를 달면 증량을 0이 아닌 값으로 바꿔야 `10*8`이 "10kg × 8회"로 읽혀요.
- 슈퍼세트 `A/B: 35*10/12*2`는 두 종목의 **무게가 같다고** 보고 읽어요. 종목 이름이 없는 줄(`삼두 슈퍼세트: ...`)은 못 읽어요.
- `바 제외`는 글자만 지우고 숫자는 그대로 써요 (바 무게를 더하지 않음). 같은 종목은 항상 같은 방식으로 적어야 비교가 맞아요.
- 성장(⑥)은 같은 분할을 **두 번 이상** 기록해야 보여요. 메모를 덮어쓰지 말고 새 회차를 아래에 추가하세요.
- 메모 형식이 다르면 "이해 못 한 줄"로 빠져요. 실제 메모에 맞춰 `parse_set`을 고치면 돼요.

## 7. 앱 (v0.4, `app/` 폴더)

헬스장에서 폰으로 입력하는 **PWA** (홈 화면에 추가하면 앱처럼 열리고, 인터넷 없이도 동작).

| 파일 | 하는 일 |
|---|---|
| `index.html` | 빈 화면 + 파일 불러오기 |
| `exercises.js` | 종목 설정 (노트북 ②의 `EXERCISES`를 옮긴 것 — **노트북에서 바꾸면 여기도 같이**) |
| `app.js` | 저장 · 버튼 동작 · 화면 그리기 · 메모 형식 내보내기 |
| `style.css` | 모양 (밝은/어두운 모드) |
| `manifest.webmanifest`, `icons/` | 홈 화면 아이콘 · 이름 |
| `sw.js` | 서비스 워커: 앱 파일을 폰에 보관 → 오프라인 동작 |
| `sync.js` | 로그인 · 동기화 (Supabase). 운동을 표 4개로 나눠 올리기 |
| `vendor/supabase-*.js` | Supabase 라이브러리 (오프라인에서도 열리게 저장소에 포함) |

**v0.4-b에서 추가:** 화면 위 스톱워치 (전체 · 휴식), 종목 카드에 "다음 목표" (노트북 ⑧과 같은 규칙: 중간에 무게를 낮춤 · RPE 10 굳히기 · 맨몸 +1회), ± 칸에 제안 무게가 미리 들어감, 요약에 평균 휴식.

**v0.4-a에서 되는 것:** 분할 선택 → 종목 검색 · 추가 (지난번 같은 분할 종목 먼저) → 무게 · 횟수 ± (증량 단위) 또는 직접 입력 → 세트 완료 → 세트 눌러서 수정 · 삭제 → 마지막 세트 RPE 7~10 → 운동 끝 (운동 시간 기록) → 메모 형식 복사. 홈에서 지난 운동 · 내보내기(전체) · 백업(JSON 파일) · 복원.

**데이터 흐름:** 버튼 → `data`(폰 저장소) → `toMemo()` → `가슴 10/05 / ◦ Bench press: 85*8,8,7 @8` → 노트북 ① MEMO 맨 아래에 붙여넣기

**배포 (Vercel):** vercel.com에 GitHub로 로그인 → Add New → Project → 이 저장소 Import → Root Directory는 그대로(`./`) → Deploy. 저장소 맨 위의 `vercel.json`이 "`app` 폴더를 보여 줘"라고 알려 줘요. Vercel **Settings → Environments → Production → Branch Tracking**을 지금 버전 브랜치(`v0.4`)로 두면, 그 브랜치에 올릴 때마다 기본 주소가 새 버전으로 바뀌어요. 다음 버전으로 넘어가면 이 칸만 바꾸세요.

**폰에 설치:** 아이폰 Safari로 주소 열기 → 공유 버튼 → "홈 화면에 추가"

**v0.4-c-1:** 홈의 ☁️ 칸에서 로그인하면 끝난 운동이 Supabase에 올라가요 (로그인 전 기록 포함, 인터넷이 다시 연결되면 자동). 데이터베이스 표 설계는 `supabase/migrations/`에 있어요: `workouts` (운동 한 번) ─< `workout_exercises` (그날 한 종목) ─< `sets` (한 줄 = 한 세트), `my_exercises` (내가 만든 종목). 모든 표에 "내 기록은 나만" 보안 규칙(RLS).

**주의:** 로그인 전에는 기록이 폰 안에만 있어요. Safari에서 웹사이트 데이터를 지우면 사라지니까 가끔 **백업**을 눌러 파일로 저장하세요.
