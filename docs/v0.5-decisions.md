# v0.5 — 네가 정할 것 (운동하는 동안 정리)

브랜치는 단계마다 하나씩 쌓았어. 앞 단계 위에 다음 단계가 올라가 있어서, 마음에 안 드는 단계가 있으면 그 **앞 브랜치**로 돌아가면 돼.

```
v0.4 ─ v0.5 (a: 종목 사전) ─ v0.5-b (식단 입력 줄이기) ─ v0.5-c (세트 메모)
```

## 0. 먼저: 폰에서 확인하는 방법
- Vercel은 브랜치마다 **Preview 주소**를 자동으로 만들어 줘 (Vercel → 프로젝트 → Deployments → 브랜치 이름). 그 주소로 열어 보면 돼.
- Preview 주소는 다른 웹사이트로 취급돼서 폰에 저장된 기록이 안 보여. **로그인하면** Supabase에서 받아 와.
- ⚠️ v0.5 이상으로 한 번 로그인하면, 옛 이름(BB row, SLL …)이 정식 이름으로 바뀌어서 Supabase에 다시 올라가. 그 뒤에 **v0.4 앱을 계속 쓰면 안 돼.** v0.4에는 옛날 "Incline bench press → Smith IBP" 이름 바꾸기가 남아 있어서, 새 정식 이름 Incline bench press(바벨, 예전 Free IBP)를 다시 Smith 쪽으로 바꿔 버려. 그래서 확인이 끝나면 Production(Branch Tracking)을 `v0.5-c`로 바꾸는 걸 추천해.

## 1. 슈퍼세트 입력 (로드맵 v0.5)
메모로는 `Cable push down/Overhead triceps extension: 35*10/12*2`처럼 적고 있어. 앱에서 어떻게 할지 골라 줘.
- **(가) 묶어서 보여 주기만** (추천): 종목 카드에 "다음 종목과 슈퍼세트" 버튼. 묶인 두 카드가 붙어 보이고, A 세트를 끝내면 B 카드가 펼쳐져. 휴식 타이머는 B까지 끝난 뒤부터. 메모 내보내기는 지금처럼 **두 줄**로 (노트북이 그대로 읽음).
- (나) (가) + 메모도 `A/B` 한 줄로 내보내기: 노트북의 슈퍼세트 읽기와 맞지만, 두 종목의 세트 수나 무게가 다르면 한 줄로 못 적어.
- (다) 아직 안 함.

## 2. 음식 DB 연동 (FatSecret)
지금은 FatSecret 화면을 보고 숫자를 옮겨 적고 있어. 앱 안에서 음식을 검색해서 넣으려면:
- FatSecret Platform API 가입 → 키 발급이 필요해 (무료 등급의 조건 · 출처 표기 의무는 가입할 때 확인 필요).
- 키를 앱(폰)에 넣으면 누구나 볼 수 있어서, **Supabase Edge Function**(서버 쪽 작은 함수)에 숨겨 두고 앱은 그 함수를 부르는 구조가 돼. 이건 지금 연결된 Supabase로 만들 수 있어.
- 정할 것: 할지 말지, 그리고 한다면 키 발급(네가 가입해야 함).
- 참고: 오늘 넣은 "최근 먹은 것 · 전날 복사"로 반복되는 식단은 이미 꽤 줄었을 거야. 써 보고 그래도 귀찮으면 그때 해도 늦지 않아.

## 3. STRAVA 연동
- Strava API 앱 등록 + 로그인(OAuth)이 필요해.
- 정할 것: **무엇에 쓸지**. 유지 칼로리는 이미 "먹은 것 + 체중 변화"로 역산해서 러닝까지 들어가 있어. 러닝 칼로리를 또 더하면 **두 번 세는** 셈이야. 그래서 칼로리 말고 "러닝 기록을 운동 그래프 옆에 같이 보기" 정도가 맞을 것 같아.

## 4. 오늘 만든 것 중 네가 확인할 것
- **v0.5-b**: "최근 먹은 것"은 8개. 너무 많거나 적으면 `app/nutrition.js`의 `RECENT_FOODS_SHOWN` 한 줄.
- **v0.5-c**: 세트 메모는 메모 형식(노트북으로 가는 글)에는 안 넣었어. 노트북은 숫자만 읽거든. 노트북에서도 메모가 보여야 하면 말해 줘.
