v0.6-d 커밋으로 `supabase/functions/food-search/index.ts`에서 raw 확인 모드를 지웠지만, **서버에 있는 함수는 네가 다시 배포해야 바뀌어.** Claude는 배포하지 않았어.
- 브라우저로: Supabase 대시보드 → 프로젝트 → **Edge Functions** → `food-search` → **Code** 탭 → GitHub의 `supabase/functions/food-search/index.ts` 내용(PR을 합친 뒤 `main`에서)을 통째로 복사해 붙여넣기 → **Deploy**
  - 30줄이 `const { q } = await req.json()…` 이고, `keyCheck`라는 글자가 어디에도 없으면 맞게 붙여넣은 것
- 배포 뒤 확인: 앱 → 식단 → 음식 추가 → "홀리닭" 검색 → 결과가 예전처럼 나오면 성공 (검색은 그대로, 확인 모드만 사라짐)
- `FOOD_API_KEY`(비밀값)는 그대로 둬도 돼. 키 앞 6자 · 뒤 4자 · 길이가 한동안 보였던 거라, 걱정되면 공공데이터포털에서 키를 새로 받아 **Edge Functions → Secrets**에서 바꾸면 완전히 안전해 (선택)

## 1. 회원가입이 열려 있음 — 어떻게 할까? (추천: 가)
지금은 앱 주소를 아는 사람 누구나 가입할 수 있어. 남의 기록은 RLS("내 기록은 나만")가 막아 줘서 **네 기록이 보이지는 않아.** 대신:
- 가입한 사람은 누구나 `food-search`를 불러서 **네 공공데이터포털 키의 하루 사용량**을 쓸 수 있어 (v0.6-d 전에는 키 조각까지 볼 수 있었음)
- 네 Supabase 무료 저장 공간에 남의 기록이 쌓일 수 있어
- (가) **가입 닫기** (추천): Supabase 대시보드 → **Authentication → Sign In / Providers** → **Allow new users to sign up** 끄기. 네 계정은 이미 있으니 로그인은 그대로 돼. 나중에 친구를 넣고 싶으면 그때 잠깐 켜거나 대시보드에서 초대(Invite user)
- (나) 열어 두고 메일 확인만 (지금 상태 그대로)
- (다) 앱의 "회원가입" 버튼도 같이 숨기기 — (가)를 고르면 버튼을 눌러도 에러 문구만 나오니까 숨기는 게 깔끔해. 고르면 Claude가 만들게
- Claude는 인증 설정을 바꾸지 않았어

## 3. 추천 섭취 바닥 1,500kcal (여 1,200) — 이 숫자 괜찮아?
- v0.6-d에서 새로 넣은 안전장치: 추천 섭취가 0이나 음수로 나오던 것(B8)을 막으려고 `MIN_TARGET_KCAL = 1500`, 내 정보 성별이 "여"면 `MIN_TARGET_KCAL_FEMALE = 1200` 아래로는 추천 안 함. 바닥에 걸리면 화면에 안내가 나옴
- 1500 / 1200은 흔히 쓰는 안내값이지 의학적 처방이 아니야. 바꾸려면 `app/nutrition.js` 28 · 29줄 한 줄씩
- 노트북 ⑤에는 바닥이 없어. (가) 노트북에도 같은 바닥 넣기 / (나) 앱에만 두기 (지금)

## 4. 이전 버전 기록의 "주인"
- v0.6-d부터 폰 기록에 주인 계정(`ownerId`)을 적어. 이전 버전에서 쓰던 기록은 주인이 비어 있어서, **v0.6-d로 처음 동기화하는 계정이 주인**이 돼
- 네 폰은 네 계정으로만 써 왔으니 문제없어. 혹시 다른 계정으로 로그인해 본 폰이 있으면, v0.6-d 첫 동기화 전에 백업을 한 번 받아 두는 게 안전해
